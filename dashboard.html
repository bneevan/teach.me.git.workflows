Branching Models • Trunk-Based Dev Answer Breakdown
✓ Core Definition
All engineers merge small, frequent commits directly into a single shared branch ('trunk' or 'main') at least once a day, avoiding long-lived feature branches.
Architectural Key Insight: Merge conflicts grow super-linearly with branch lifespan. TBD eliminates merge debt by forcing continuous daily integration.

Architectural Trade-Off & Comparison Matrix
Workflow Strategy Release Cadence Merge Lifespan CI/CD Requirement Rollback / Recovery Ideal Team & Context
● Centralized Ad-hoc / Manual 0 (Commit directly or local rebase) Minimal (often optional) High friction (reverts on main) 1-3 developers, SVN migrants, solo projects
● GitHub Flow Continuous (Daily / Multiple per day) Hours to a few days Strict automated tests & deployment gates Fast (revert PR or redeploy prior commit) Web applications, SaaS, microservices, startups
● Trunk-Based Dev Continuous / On-demand Sub-24 hours (< 1 day) Essential (ultra-fast CI, Feature Flags) Instant via Feature Flag toggle (zero redeploy) High-velocity engineering (Google, Netflix, Meta), mature CI
● Gitflow Scheduled / Batched (bi-weekly, monthly) Days to weeks (feature & release branches) Standard automated builds Medium (dedicated hotfix branches to main & develop) Boxed enterprise software, multi-version maintenance, mobile apps
● Fork & Pull-Request Release-driven or continuous Varies by contributor Strict automated sandboxed CI for PRs Maintainer-driven revert Open Source, untrusted multi-party contributors, contractors
● GitOps Continuous automated sync Driven by trunk merges or image tags Kubernetes / declarative engine + ArgoCD/Flux Instant git revert triggers automated downward reconciliation Cloud-native infrastructure, Kubernetes clusters, zero-drift platforms
Course Mission & Educational Principles

Why We Are Here

To elevate your Git fluency from basic command memory (add, commit, push) to high-level architectural decision-making. You will learn to evaluate how team topology, deployment constraints, release frequency, and code ownership determine the right workflow.

Teaching Contract:

  • One concept at a time: No knowledge dumps. Each step builds on verified understanding.
  • Active Socratic engagement: You will be asked to analyze scenarios, predict merge behaviors, and resolve dilemmas.
  • Progressive artifact generation: Lessons, reference cheat sheets, and learning records will be persisted in this workspace.
