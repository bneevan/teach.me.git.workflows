Reference Sheet: Git's DAG & Object Model

💡 The Immutable Law of Git

Git does not track file diffs or deltas. Git tracks snapshots in an immutable, content-addressed Directed Acyclic Graph (DAG). Every commit points backwards to its parent(s).

1. The Four Fundamental Git Objects

1. Blob (Binary Large Object)

Stores raw file contents only. No file name, no timestamp, no file permissions.

SHA = hash(size + content)

2. Tree

Represents a directory. Maps file names, modes, and permissions to Blob SHAs or nested Tree SHAs.

100644 blob a1b2... main.py

3. Commit

A small text metadata file pointing to a root Tree SHA, parent commit SHA(s), author, committer, and message.

tree 7f8a...
parent 3b2c...

4. Annotated Tag

An immutable pointer to a specific commit, containing a tagger name, date, and verification message/PGP signature.

object 4c1d... tag v1.0.0

2. Directed Acyclic Graph (DAG) Anatomy

HEAD -> [ main ] (pointer) | v (Commit C3) [hash: 9a2f] -> points to [Tree 88cc] (Full Snapshot) | parent v (Commit C2) [hash: 5d1e] -> points to [Tree 44bb] | parent v (Commit C1) [hash: 1a0b] (Initial commit, zero parents)

3. What is a "Branch" Really?

In Git, a branch is not a directory of copied files. A branch is simply a 41-byte text file in .git/refs/heads/<name> containing the 40-character hexadecimal SHA-1 (or 64-character SHA-256) of its latest commit!

$ cat .git/refs/heads/main 9a2f64c810d2975975db3588ef11b7a69b7f584e

Moving a branch or making a new branch has O(1) constant time complexity and costs virtually zero disk space.
