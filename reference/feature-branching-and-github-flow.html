Reference Sheet: Feature Branching & GitHub Flow

💡 The Core GitHub Flow Principle

There is strictly one permanent branch: main. Anything in main is deployable to production. All new work happens on short-lived feature branches reviewed via Pull Requests and deployed continuously.

1. The 6 Rules of GitHub Flow

  1. Deployable Main: Anything in the main branch is deployable to production at all times.
  2. Descriptive Branch Off Main: Create a short-lived branch directly off main with a descriptive name (e.g. feat/user-avatar or fix/csrf-token).
  3. Push Regularly: Push your branch to the remote early and often so work is visible, backed up, and testable by CI.
  4. Open a Pull Request (PR): Open a PR early to solicit code review, trigger automated test pipelines, and discuss implementation trade-offs.
  5. Merge After Approval: Once automated checks pass and team reviewers sign off, merge into main.
  6. Deploy Immediately: Deploy immediately upon merge to production (or staging -> prod via continuous deployment).

3. Pull Request Merge Strategies Compared

1. Create Merge Commit

Retains full branch history with a 2-parent merge commit (Merge pull request #42).

Best for: Preserving original branch shape and independent commit identities.

2. Squash and Merge

Combines all branch commits into a single atomic commit on main.

Best for: High-velocity web teams wanting pristine, revertible, bisectable main history.

3. Rebase and Merge

Replays individual commits linearly onto main without a merge commit.

Best for: Teams enforcing disciplined atomic commits who want a 100% linear history.

4. Branch Protection Rules: The Safety Net

Modern engineering teams protect main against human error using repository settings:

  • Require Pull Request Before Merging: Completely disables direct git push origin main.
  • Require Approvals: Enforces minimum peer sign-offs (e.g. 1 or 2 senior reviews).
  • Require Status Checks to Pass: Automated test suites, linting, security scans, and build steps must be green before the merge button unlocks.
  • Require Conversation Resolution: Blocks merging if any code review comment remains open.
