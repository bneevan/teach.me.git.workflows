Lesson 01: The DAG & Snapshot Architecture

🎯 Single Tangible Win for this Lesson

Replace the "delta / diff list" misconception with the exact mental model used by senior staff engineers: Git is a Directed Acyclic Graph of root tree snapshots, navigated by movable pointer references.

1. The Mental Shift: Deltas vs. Snapshots

Older systems like Subversion (SVN) and CVS conceptualized version control as a base file plus a sequential chain of diff deltas. When you asked for version 5, the server computed: Base + Delta1 + Delta2 + Delta3 + Delta4.

Delta-Based VCS (SVN, CVS)

Stores a baseline file and a series of change deltas for each revision. Branching copies whole directory trees on the central server.

Snapshot-Based DAG (Git)

Every commit points to a full root filesystem snapshot. Unmodified files share exact SHA pointers (zero duplicated disk space).

2. What is a "DAG" in Git?

DAG stands for Directed Acyclic Graph:

  • Graph: A network of nodes (Commits) connected by edges.
  • Directed: Edges have a strict one-way direction: children point back to their parent(s). A commit knows its parent, but a parent never knows what future commits branch off it.
  • Acyclic: It is mathematically impossible to have a loop or cycle. A commit cannot be its own ancestor.
Commit C3 (SHA: 9a2f...) --> points backwards to Parent C2 | v (parent pointer) Commit C2 (SHA: 5d1e...) --> points backwards to Parent C1 | v (parent pointer) Commit C1 (SHA: 1a0b...) --> Root commit (0 parents)

3. What is a "Branch"?

A branch is nothing more than a movable named pointer pointing to a single commit node in the graph. When you create a branch:

git branch feature

Git does not clone your files or duplicate your project. Git merely writes a 41-byte text file named .git/refs/heads/feature containing the SHA of your current commit! Making 10,000 branches in Git takes milliseconds and virtually zero memory.
